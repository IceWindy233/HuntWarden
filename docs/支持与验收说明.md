## 1. 状态口径

- `已验证`：对应自动化或明确记录的环境已经实际通过。
- `ENGINEERING_PASS`：当前工程主链和已有环境门禁通过。
- `RELEASE_BLOCKED`：稳定发布缺少最终同提交正式资格、独立盲测或可追溯的责任声明；旧提交与开发演练结果不能补为当前发布资格。它不禁止按下述边界交付明确标识的预发布文档和测试资产。
- `待实机验收`：代码路径或容器场景可能可用，但没有对应平台的真实主机证据。
- 环境门禁未执行或被跳过时，不计为通过。
- `PARTIAL`、`ERROR`、`NOT_RUN`、`UNKNOWN` 只表示调查不完整，不表示目标安全。

**当前预发布执行口径**：项目维护者已于 2026-09-13 明确授权助手在自有隔离部署执行验收并整理发布文档，执行者须如实记为 `AI/automation`，PR 由维护者完成。业务/平台所有者指验收部署责任人，可由维护者委托实际核对，无需上游或生产用户代签；这不是独立第三方验证或生产用户背书。授权来源、范围、执行者、时间和冻结清单摘要须按[单维护者预发布执行边界](../acceptance/release/README.md)留存；平台来源/摘要及本次串口等带外 Host Key 必须真实核对，业务端点语义、组件和性能门槛必须在新运行前冻结。

以下历史 `UNCONFIRMED`、`DEVELOPMENT` 和首跑/失败记录不因此改变；新一轮须使用新的仓库外目录与新原件，只回填实际观测。预发布须保留通知文件、资产摘要和 Prerelease 标识；可交付发布文档不等于稳定资格获准，稳定版本仍须具备同一干净固定提交的完整证据及满足原统计和隔离门禁的 `BLIND_RELEASE`。

### 3.1 自主调查控制面

当前工程实现包含易失优先发现、持久化 Lead/Hypothesis/Obligation/Action、自动分页、增量规则、四个版本化流程包、结构化模型提案、Evidence 保全、暂停/恢复/取消、完成快照、GUI/报告投影和 evaluator schema v2。4 恶意 + 4 良性 + 4 受限控制端场景全部通过；该小矩阵用于验证状态机和归因，不能替代正式质量盲测。

模型为空响应、流中断或 Provider 失败时，确定性结果不丢失；运行时有界重试，并在调查轮次内持久化补齐模型 Hypothesis、Action 和终态 Assessment 的提示。OpenAI Chat Completions 与 Responses 的本机 HTTP/SSE 契约 1/1 通过：两种协议均实际发送请求并验证工具 Schema、流式 Tool Call 参数重组和 usage；故障矩阵完成 429→200 有界重试及逐次状态审计、流中停滞中止和空响应拒绝。发布资格由 `qualify:provider:tasks` 从仓库外 YAML 创建并闭合 Linux/Java 任务，再由 `qualify:provider` schema v2 在线冒烟并核验模型提案/动作/裁定、发现检查点、完成快照、冻结报告和 Java Evidence 引用，同时交叉绑定本机故障契约、当前控制端提交和 Helper 源码摘要。

2026-09-09 在提交 `9b1ea145b4cb4f666eff9c3abd412889ddf51505` 上使用 `tokenrhythm/glm-5.3-flash` 完成一组真实联合任务：Linux 零 IOC 调查为 `CLOSED_NO_OBSERVED_FINDING`，18/18 次 Provider HTTP 成功，4 个 MODEL Action 均成功；Java 调查为 `CLOSED_WITH_FINDINGS`，21/21 次 Provider HTTP 成功，17 条类字节码 Evidence 全部完整且校验通过，其中 9 条被模型引用。模型保留内容级检测、未知 loader 和未挂接组件范围缺口，类别终态为 `INCONCLUSIVE`，没有把有限可见性写成安全。正式生成器复核了上述任务语义，但本机透明代理把系统 DNS 映射到 RFC 2544 fake-IP，旧门禁因此返回 FAIL。提交 `b9d6ea3704fdd7efdecbf7fa2dab687c9d7f7648` 已增加仅限该 fake-IP 场景的 TLS DoH 取证，在线复核得到稳定的两个公网地址并将端点归类为 `REMOTE_VENDOR`。

历史同提交联合任务及后续修复记录见[后续工作路线](后续工作路线.md#42-hw-013-固定提交发布证据已完成)。`b03667a8e09b9ac77565ea0e263f3b7323a2672d` 已完成真实 Provider PASS；本轮源码和 Helper 已变化，必须在最终干净提交重跑，不能继续引用旧证据关闭本轮发布。

## 4. 数据与处置边界

- Fact、Object、Cursor、Query、Evidence、Grant、Budget 和 Action Receipt 全部绑定 task、epoch 与目标身份。
- 模型只能查询 Model Fact；Private Fact、Evidence bytes、数据库路径、Artifact Token、Spool 路径和 Provider 原始响应不可见。
- 有界采集达到节点、字节或时间上限时返回 `PARTIAL` 和结构化 Gap。
- `SCAN` 不注册写工具；默认 `REMEDIATE` 只开放 `quarantine_file`，并要求完整 Evidence、一次性审批票据和目标端原子回执。
- `disable_account` 未覆盖活动会话、`authorized_keys`、SSH CA/principals 与恢复验证，默认关闭。
- `restore_quarantined_file` 与 `restore_account_state` 尚未实现，真实目标应优先使用 `SCAN`。

## 7. 真实主机验收流程

1. 仅在已授权、可销毁的临时 VM 中验收，先安装依赖和 Helper，并执行 `self-check-helper.sh`。
2. 通过带外通道核验 Host Key，再写入专用 `known_hosts`。
3. 先运行只读 QUICK/STANDARD，确认依赖缺失、权限不足和数据源缺失均呈现为 Gap，而非安全结论。
4. 在 GUI 中覆盖五类检测和所需 Profile，记录 Coverage、Assessment、Evidence、ToolRun、耗时与预算。
5. 使用固定无害阳性和良性对照；确认未选择类别的工具调用数为 0，SCAN 成功写操作数为 0。
6. 运行模型统计评测、RE2 和发布层门禁，保留首跑异常，不用重跑结果覆盖失败记录。
7. 清理夹具、凭据、VM/容器和产物；只按实际平台、架构、依赖与 Provider 配置更新本文。

验收记录至少包含：结论、执行人和时间、commit、Epoch 控制端提交、Helper SHA-256、镜像来源与 ID、发行版/架构/内核、Helper 版本、Host Key 核验、依赖降级、五类 Profile 结果、样本与良性对照、性能预算、缺陷、报告 SHA-256 和清理状态。禁止保存私钥、API Key、完整 SSH Key、真实凭据或原始敏感 Evidence。
