# HuntWarden 支持与验收说明

| 项目 | 当前值 |
| --- | --- |
| 更新日期 | 2026-09-01 |
| 当前基线 | Tool Protocol v2，Manifest/Helper `2.1.0` |
| 综合结论 | `PASS_WITH_LIMITATIONS` |

本文是当前支持范围、验证门禁和发布验收结果的单一入口。历史版本说明见 [`版本发布说明.md`](版本发布说明.md)；计划中的能力不得据此描述为已经支持。

## 1. 状态口径

- `已验证`：对应自动化或明确记录的环境已经实际通过。
- `PASS_WITH_LIMITATIONS`：主要链路通过，但仍有明确的稳定性或覆盖限制。
- `待实机验收`：代码路径或容器场景可能可用，但没有对应平台的真实主机证据。
- 环境门禁未执行或被跳过时，不计为通过。
- `PARTIAL`、`ERROR`、`NOT_RUN`、`UNKNOWN` 只表示调查不完整，不表示目标安全。

## 2. 接入与平台支持

### 2.1 目标接入

| 项目 | 状态 | 说明 |
| --- | --- | --- |
| Linux over SSH | 已验证 | 严格绑定 host、port 与 Host Key；未知 Key 必须人工确认，变化或撤销会阻断连接。 |
| SSH 私钥文件 | 已验证 | 支持无交互 Ed25519 私钥；配置仅保存绝对路径。 |
| IPv6 | 代码路径可用，待实机验收 | Host Key 绑定支持 IPv6 表达，尚无真实 VM 记录。 |
| SSH Agent、加密私钥、ProxyJump | 未实现 | 当前只支持无交互私钥文件和直连 SSH。 |
| Local、Collector、Offline、WinRM | 未实现 | 不得把 SSH 调查描述为其他接入方式。 |

## 3. 检测能力

| 检测包 | 已验证能力 | 主要限制 |
| --- | --- | --- |
| WebShell / Web 攻击链 | Nginx/Apache 技术栈与有效 Web Root、近期候选、固定 RuleSet YARA、literal/RE2、Access Log、文件/进程关系、受控文本读取与 Evidence 隔离 | 复杂 Apache/PHP-FPM Include、真实站点误报率与时间戳回改尚未验证。 |
| Java 内存马 | Tomcat 9/JDK 17 的组件枚举、Spring MVC、ClassLoader/CodeSource/ProtectionDomain 与只读 Class Dump | Tomcat 8.5/10 与 JDK 8/11/21 尚未验证。 |
| 后门账户 | UID 0、sudo/wheel、账户状态、SSH Key 指纹、sudoers/doas/polkit、`sshd -T` 默认上下文与登录历史 | `sshd Match` 逐用户/来源上下文、SSSD/LDAP 与云登录日志尚未覆盖。 |
| Linux 持久化 | Cron、systemd、at/anacron、SysV/rc.local、XDG、PAM、udev、modprobe、cloud-init 与包管理 Hook | initramfs 内容和 transient unit 的完整 D-Bus 运行态详情尚未实现。 |
| Linux 入侵分诊 | 稳定进程身份、进程关系、Socket、删除后运行、固定 Scope、dpkg/rpm inventory、`package_db` 抽样验证、动态加载与时间线 | Scope 与包校验为有界抽样；wtmp/btmp、独立 sudo 日志和 journal 增量采集尚未实现。 |
| 安恒威胁情报富化 | 当前任务公网 IOC 引用、批量查询、本地缓存、Evidence、审计与 GUI 情报视图 | 外部命中不能单独形成 `CONFIRMED_MALICIOUS`。 |

Helper 只接受协议 2 的 `capabilities` 和八个静态白名单只读原语。Capability 只能收紧 Manifest；依赖或权限缺失必须形成 Gap 并降低 Coverage。安装和自检见 [`../host-helper/README.md`](../host-helper/README.md)。

## 4. 数据与处置边界

- Fact、Object、Cursor、Query、Evidence、Grant、Budget 和 Action Receipt 全部绑定 task、epoch 与目标身份。
- 模型只能查询 Model Fact；Private Fact、Evidence bytes、数据库路径、Artifact Token、Spool 路径和 Provider 原始响应不可见。
- 有界采集达到节点、字节或时间上限时返回 `PARTIAL` 和结构化 Gap。
- `SCAN` 不注册写工具；默认 `REMEDIATE` 只开放 `quarantine_file`，并要求完整 Evidence、一次性审批票据和目标端原子回执。
- `disable_account` 未覆盖活动会话、`authorized_keys`、SSH CA/principals 与恢复验证，默认关闭。
- `restore_quarantined_file` 与 `restore_account_state` 尚未实现，真实目标应优先使用 `SCAN`。

## 6. Ubuntu 24.04 ARM64 发布基线

### 6.1 实机与 GUI Profile

- 执行时间：2026-08-30 至 2026-09-01（Asia/Shanghai）。
- 环境：Canonical Multipass Ubuntu 24.04 ARM64 临时 VM、真实 SSH、root Helper `2.1.0`、Electron GUI。
- Provider：`siliconflow/deepseek-ai/DeepSeek-V4-Flash`。
- 正式矩阵：五类检测分别运行 QUICK、STANDARD、DEEP，共 15 个完成任务、152 次 ToolRun、60 轮，失败调用 0、成功写操作 0。
- WebShell 三档均为 `COMPLETE/APPLICABLE`；Java 三档在无 JVM 目标上为 `COMPLETE/NOT_APPLICABLE`；账户、持久化和分诊因有界数据源保持 `PARTIAL/UNKNOWN`，模型均以 `INCONCLUSIVE` 收尾。

## 7. 真实主机验收流程

1. 仅在已授权、可销毁的临时 VM 中验收，先安装依赖和 Helper，并执行 `self-check-helper.sh`。
2. 通过带外通道核验 Host Key，再写入专用 `known_hosts`。
3. 先运行只读 QUICK/STANDARD，确认依赖缺失、权限不足和数据源缺失均呈现为 Gap，而非安全结论。
4. 在 GUI 中覆盖五类检测和所需 Profile，记录 Coverage、Assessment、Evidence、ToolRun、耗时与预算。
5. 使用固定无害阳性和良性对照；确认未选择类别的工具调用数为 0，SCAN 成功写操作数为 0。
6. 运行模型统计评测、RE2 和发布层门禁，保留首跑异常，不用重跑结果覆盖失败记录。
7. 清理夹具、凭据、VM/容器和产物；只按实际平台、架构、依赖与 Provider 配置更新本文。

验收记录至少包含：结论、执行人和时间、commit、镜像来源与 ID、发行版/架构/内核、Helper 版本、Host Key 核验、依赖降级、五类 Profile 结果、样本与良性对照、性能预算、缺陷、报告 SHA-256 和清理状态。禁止保存私钥、API Key、完整 SSH Key、真实凭据或原始敏感 Evidence。
