## 2. 当前实现基线

控制端已经建立持久化调查会话、实体版本、关系来源、Lead、Hypothesis、Obligation、Action/Attempt、事件水位、发现检查点和完成快照。易失发现先于完整 Preset，规则和流程包按新 Fact 增量触发；模型只能通过结构化假设、动作提案和受限查询参与，所有远程动作仍编译为八个取证原语并进入同一调度器。

当前端到端链支持：零 IOC/单线索发现，socket/进程/映像或脚本/启动来源关联，包基线和良性解释检查，删除后运行映像与 JVM 类字节码保全，Web/账户/持久化/Java 跨类别调查，以及 `CLOSED_WITH_FINDINGS`、`CLOSED_NO_OBSERVED_FINDING`、`LIMITED`、`CANCELLED` 的独立完成判定。

新建 Epoch 同时固定控制端完整提交和目标 Helper 源文件 SHA-256；恢复时任一身份变化都会失败关闭。ToolRun、模型消息、待处理输入、审批、动作回执、Evidence 和冻结报告均按当前 Task + Epoch 投影；跨 Epoch ToolCall 复用、终态重放、Evidence 来源/摘要冲突和报告文件篡改会失败关闭。正式 Provider、业务 JVM 与平台资格结果使用 schema v2 并交叉绑定该 Helper 摘要，发布包必须包含由干净提交生成的 `dist/build-identity.json`。

## 4. 剩余执行顺序

### 4.1 已完成的规模验收

`acceptance/load` 在 Ubuntu 22.04 ARM64 一次性容器中实际创建进程、文件和轮转日志，并经生产 Helper 逐页耗尽 Cursor。1000 子进程场景返回 1001 个夹具进程、100001 个文件和 100000 条日志，完整耗时 74.256 秒；10000 子进程场景返回 10001 个夹具进程、100001 个文件和 100000 条日志，完整耗时 79.373 秒。两组结果的返回数、唯一身份/路径和扫描数均一致，退出后容器与网络已清理；机器可读结果保存在对应 `result-*.json`。

### 4.2 真实 Provider 验收并关闭 HW-013/HW-017

2026-09-08 已使用仓库外配置和环境变量凭据实际运行 SiliconFlow `deepseek-ai/DeepSeek-V4-Flash`：`model:check` 与一次在线 Tool Call 冒烟通过，冒烟记录为 input 351、output 99。随后 FIRST Linux 联合任务的 Task/Epoch 和两个 Coverage 均完成，但模型无条件重枚举持续变化的 `exec_event`/`auth_event`，正确产生 `SOURCE_CHANGED` 并令调查为 LIMITED；该实测推动控制端增加提案整批语义校验及 Preset 已覆盖 namespace 的重复枚举门禁。修复后的重跑先遇到一次缺失 `finish_reason` 的不完整流，后续请求返回厂商 HTTP 402；2026-09-09 额度更新后，当前安全存储中的凭据被端点以 HTTP 401 拒绝，因此当前提交仍没有 PASS 资格结果。以上失败记录保留在仓库外，不能改写成成功。

本机 `npm run test:acceptance:provider-contract` 已让 `openai-completions` 与 `openai-responses` 各经过一次真实 TCP/HTTP/SSE 调用，核对 Authorization 占位头、模型/消息/工具 Schema、拆分的 Tool Call 参数、完成原因和 token usage；同一矩阵还验证首次 429 后仅重试一次并记录 429→200、首分片停滞中止且生产运行时归类 `PROVIDER_FAILURE`、空 assistant 不通过冒烟。该证据只关闭协议适配、故障边界与网络栈风险。

1. 在不把凭据写入仓库的前提下，为 Manifest `3.0.0` 配置一个真实支持 Tool Call 的 Provider；从干净固定提交重跑 `npm run test:acceptance:provider-contract`。
2. 使用 `qualify:provider:tasks` 从严格 Linux/Java 目标 YAML 依次运行零 IOC Linux 链、模型新增 Hypothesis/Action 链和 Tomcat 9/JDK 17 链；保存空响应、429、流中停滞、非法引用与重试的每次独立记录。运行器只接受仓库外数据/输出目录，Task、Epoch 或调查未闭合即失败并写出首跑状态。
3. 核对模型提案只产生白名单 Action，直接调用与提案不会重复远程执行，Provider 失败时确定性义务仍完成且模型审查明确 LIMITED。
4. Java 案例必须由模型读取调查摘要并提出或复核精确 loader 组合，最终报告引用实际类字节 Evidence。
5. 使用 `npm run qualify:provider -- --config <配置> --data-dir <数据目录> --linux-task <任务> --java-task <任务> --provider-contract <契约结果> --output <仓库外结果>` 生成正式证据。schema v2 生成器会核对任务/Epoch/完成快照、发现检查点、Provider HTTP 尝试、两种提议 Tool Call、MODEL Action/Attempt、Assessment、绑定当前 Epoch 的冻结报告、重复执行、Java Evidence 引用、Epoch 控制端提交与 Helper SHA-256，并要求在线冒烟前后 DNS 集合稳定且全部为公网地址；任何一项不能由执行记录证明即返回 FAIL。

### 4.3 独立盲测并关闭 HW-018
