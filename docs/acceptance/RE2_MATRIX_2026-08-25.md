# RE2 平台语义矩阵（2026-08-25）

## 结论

Tool Protocol v2 的 RE2 Matcher 在 macOS ARM64 和 Ubuntu 22.04 ARM64 上均通过生产 Helper 真路径验证。两端都完成实际匹配，并把 RE2 不支持、但 Python `re` 支持的反向引用拒绝为 `INVALID_ARGUMENT`；不存在语义回退。

| 平台 | Python | RE2 wheel | 实际匹配 | 反向引用 | 结果 |
| --- | --- | --- | --- | --- | --- |
| macOS Darwin 25.6.0 ARM64 | 3.11.9 | `google-re2==1.1.20251105`（临时 venv） | PASS | `INVALID_ARGUMENT` | PASS |
| Ubuntu 22.04 ARM64 容器 | 镜像系统 Python 3 | `google-re2==1.1.20251105` | PASS | `INVALID_ARGUMENT` | PASS |

本次 Ubuntu 镜像 ID 为 `sha256:2b681737bbe1f537f8442fa1a3cd7a03225de8db9980ecee02c4dfab24cc3231`。镜像 ID 只用于本次记录；可复现入口会按 Dockerfile 重新构建，不把本地缓存视为信任来源。

## 复现

```bash
npm run test:acceptance:re2
```

脚本在临时 venv 中验证控制端同平台 Helper，再构建固定 Ubuntu 22.04 容器。测试文件只写入 Helper 所在测试目录并在结束时删除；不会连接 SSH 目标、不会执行处置动作。YARA 的 Ubuntu 真路径由五套 Docker Lab 中的固定 `RULESET-WEBSHELL-BUILTIN-2` 匹配覆盖。
