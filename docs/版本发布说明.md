# HuntWarden 版本发布说明

本文合并各版本面向用户的发布摘要。完整逐项变更仍以根目录 [`CHANGELOG.md`](../CHANGELOG.md) 为准；当前支持边界以 [`支持与验收说明.md`](支持与验收说明.md) 为准。

## 下一版本候选（未发布，2026-09-08 工程基线）

自主深度取证主链已经按 Manifest/Helper `3.0.0` 实现：易失优先发现、持久化调查状态机、增量规则与流程包、结构化模型提案、自动分页、Evidence 保全、独立完成校验、GUI/报告投影和端到端 evaluator 均已接入生产运行时。

当前工程验收包括控制端 4 恶意 + 4 良性 + 4 受限场景、两种 OpenAI-compatible 协议的本机 HTTP/SSE 契约 1/1、Docker 五类 Lab 14/14、Debian 动态 SSH 6/6、Ubuntu 24.04 ARM64 smoke 4/4、journald 1/1 与 systemd transient unit 1/1、GUI 16/16、RE2 双环境和 Tomcat 9/JDK 17 真探针。协议契约实际核对请求、工具 Schema、流式 Tool Call 分片重组、完成原因和 usage；故障矩阵完成 429→200 逐次审计、105 ms SSE 停滞中止和空响应拒绝，但不替代真实厂商 Provider。systemd 专项验证运行态 transient fragment、active/命令/执行文件关系，并在清理后带外核对为 `LoadState=not-found`。Docker Tomcat 部署固定摘要的 Spring MVC 5.3.39，实际发现 `/spring/health` Controller、Interceptor 和 `/ws/{id}` WebSocket endpoint，并在静态页/Spring Controller 混合的持续 8 路 HTTP 流量下完成 12 次连续受控 Attach：1,758 次请求零失败，负载 P95 2 ms、最大 5 ms，Attach 最慢 82 ms，动态 Filter、WebSocket、Spring Controller 与 Interceptor 均无漏检，原始 JVM identity 保持稳定且每次均有可审计成本；1001/10001 个真实进程、100001 个文件与 100000 条轮转/gzip 日志的生产 Helper 分页已在 Ubuntu 22.04 ARM64 容器通过。生产控制端规模链在 1 千/1 万进程下均于末页前保全首屏异常执行体，完整耗时 4.078/22.627 秒，首 Evidence 593/590 ms，Observation 提交至 Evidence 为 216/221 ms，50 ms 采样最大 RSS 195.4/673.5 MiB；动态 SSH 场景还以 256 KiB 固定分块完成 100 MiB Evidence 的端到端字节数和 SHA-256 核对。空 assistant 会保留原始轨迹并将模型审查降为 LIMITED；队列容量、自动翻页、Apache/PHP-FPM、SSH Match、wtmp/btmp、systemd drop-in 和类字节码 Evidence 已纳入回归。

发布资格已提供 schema v2 可执行生成路径：真实 Provider 结果必须来自在线冒烟、两个完整 RuntimeStore 任务与协议故障契约，并证明冒烟前后 DNS 集合稳定且全部为公网地址；真实业务 JVM 必须在冻结业务流量下连续 Attach；平台结果必须由 Helper 观测发行版、PID 1 与 SELinux，并实际完成 Evidence 传输、清理和 SSH 重连。三类结果均绑定当前 Helper 源码摘要，Provider 任务还绑定 Epoch 的控制端提交。发布包写入干净提交身份并验证其进入 `app.asar`；发布校验器逐字段验证这些结果，手写模板不能通过。

该版本尚未发布。缺少 Manifest `3.0.0` 真实 Provider 联合验收、至少 100 恶意 + 100 良性独立盲测、真实业务 Attach 专项负载、扩展发行版矩阵，以及从干净固定提交生成的发布资产。达到这些条件前不得把本节当作 Release 成绩。

## v0.2.0（2026-09-01）

v0.2.0 将生产调查链路完整切换到 Tool Protocol v2。新任务只运行 v2 Epoch；模型使用八个受限取证原语，Helper Observation 经 Manifest 校验后原子写入 Fact Store，再由本地查询、Coverage 和 RULE/MODEL/HUMAN Assessment 独立呈现。

### 主要变化

- Manifest/Helper 升级到 `2.1.0`，补充委派规则、SSH 有效信任配置、固定 file Scope 与 `package_db` 有界验证链路。
- 删除运行时 v1 operation map、旧问题型工具面和旧 Finding 结论平面；v0.1.x 历史任务仅保留只读元数据、Evidence 和已有报告。
- 五类检测迁移为版本化 Preset、CoverageRun 与不可互相覆盖的 Assessment。
- Object、Cursor、Query、Evidence、Grant、Budget 与 Action Receipt 全部绑定 task、epoch 和目标身份；不兼容引用与越权请求失败关闭。
- 增加 Fact Store、Dataset Registry、RE2 双平台矩阵、v1→v2 能力等价门禁、四套 GUI E2E、真实 VM/journald 验收和冻结模型评测。
- 默认处置白名单只开放 `quarantine_file`；`disable_account` 因信任面和恢复链路不完整而保持关闭。

### 验证与限制

- PR、构建和静态门禁通过；Docker Lab 11/11、Debian 动态场景 5/5、GUI E2E 16/16。
- Ubuntu 24.04 ARM64 上完成 smoke 4/4、journald 1/1、模型评测 7/7，以及五类 × QUICK/STANDARD/DEEP 的 15 个正式任务。
- Provider 首跑出现过一次空响应和两次非法引用，控制端均按预期处理，因此综合结论为 `PASS_WITH_LIMITATIONS`。
- 这是破坏性展示升级：v0.1.x Finding 不再由 v2 UI/TUI/报告读取，但数据库行不会被删除。
- 目标端必须使用匹配的 Helper `2.1.0`；恢复动作、更多发行版与 JVM 版本仍待实现或验收。

## v0.1.1（2026-08-21）

v0.1.1 是 Electron GUI 补丁版本，不改变安全边界、Helper 协议、模型调用方式或任务数据格式。

- 修复任务侧栏和长详情内容无法滚动的问题，并补充语义化区域与无障碍标签。
- 修正 Grid/Flex 最小高度约束，使固定窗口内形成真实溢出区域。
- 发布脚本只收集版本号精确匹配的 ZIP/DMG，避免历史构建产物混入。
- 自动化测试 131 项通过、34 项跳过，GUI 调查 E2E 4/4 通过。

## v0.1.0（2026-08-20）

首个公开版本提供五类 Linux 主机专项检测、可追溯 Evidence/Finding、逐动作审批、崩溃恢复和版本化 Markdown 报告。

### 核心能力

- WebShell、Tomcat 9/JDK 17 Java 内存马、后门账户、Linux 持久化与 Linux 入侵分诊。
- 安恒威胁情报只富化当前任务内已经观测或由分析师预置的 IOC。
- SSH Host Key 严格绑定；Helper 只接受固定操作和 JSON 参数，不提供任意命令执行。
- `SCAN` 没有写工具；`REMEDIATE` 的每个动作均需一次性授权。
- 原始 Evidence 不进入模型上下文，采集缺口不会被描述为安全。

### 历史限制

v0.1.0 仅支持单台 Linux 主机直连 SSH；缺少 root、YARA、日志或 JDK Attach 时能力会降级；macOS arm64 开发包未签名或公证。该版本的 V1 验收结果已经被 v0.2.0 的 V2 基线取代，不作为当前支持证据。

## 安装与校验

从对应 GitHub Release 下载 `.zip` 或 `.dmg` 以及 `SHA256SUMS`，在 macOS 上执行：

```bash
shasum -a 256 -c SHA256SUMS
```

从源码复现时切换到对应 tag，再执行：

```bash
npm ci
npm run build
npm test
npm run probe:build
```

发布资产必须从最终 tag 对应的干净工作树生成。开发包尚未使用 Apple Developer ID 签名或公证；只调查你拥有或明确获授权的主机。
