## 1. 交付目标与实施边界

把现有“Preset 采集后由模型继续调用工具”的运行方式，升级为持久化调度器驱动的调查循环：持续发现对象、生成线索、提出假设、完成必要检查、保存证据、检查反证、验证结论与完成条件。

八个远程原语继续承担目标端操作。调查流程、状态机、模型提议和结论验证位于控制端。第一条交付链为：

```text
未知外连或零 IOC
→ 发现并绑定 socket 与进程
→ 执行映像 / 解释器脚本 / 父子进程
→ 启动来源 / 会话 / 持久化
→ 良性解释与基线验证
→ 原始证据保全
→ 有依据的发现或明确受限的报告
```

首个可用版本限定单台 Linux 主机、单活动任务和 SSH 接入。先在 Ubuntu 24.04 ARM64 与 Tomcat 9/JDK 17 的已知环境上建立回归，再逐项扩大发行版与运行时矩阵。容器 namespace 身份先纳入模型，跨容器采集必须在对应能力和授权验收后开放。

初始入口、历史执行或网络行为缺少可用记录时，系统必须说明受限环节。任务成功执行、局部恶意确认、调查闭合分别表示，不以“完成”暗示主机已排查干净。

### 1.1 首个端到端版本的完成条件

1. 只提供主机与一个网络线索，或不提供 IOC；运行端不能访问场景答案。
2. 自动创建并推进线索和调查义务，模型空响应或提前停止不会丢失义务。
3. 正确绑定进程、文件与直接关系；PID 复用、对象变化和推断关系有明确处理。
4. 完成关键样本保全；无法保全时保留具体原因和受影响结论。
5. 输出支持证据、反证、来源和未完成调查项。
6. 断线或控制端重启后可恢复有界读取；未知侵入式操作不盲目重放。
7. 同一条流程通过恶意、良性、缺失数据和预算受限测试。

## 3. 版本与数据迁移方案

### 3.1 将契约修复和语义升级分别交付

- M0 修复现有契约内的错误：参数覆盖、分页、Java 字段适配、部分失败传播和证据错绑。涉及对象身份变化的部分转入新 Manifest，不在旧 Epoch 中改变身份解释。
- M1 冻结新契约。拟使用 Manifest `3.0.0` 表示身份、来源和授权语义升级；具体版本由 HW-005 在开发开始时写入兼容矩阵。Wire Envelope 能否保留 `protocolVersion=2` 以实际结构兼容性为准，不能只改版本常量。
- 应用、Helper、Manifest、规则、流程包、数据库和 GUI API 分别记录版本及摘要。任务启动时固定整组版本。
- 旧任务的 Fact、引用、Coverage、Assessment 与 Evidence 保持原解释；新调查创建新 Epoch。只有兼容矩阵支持的进行中任务可以恢复，其他任务保留现场并引导创建新调查。

### 3.2 数据结构与约束

保留 `facts_v2` 中的不可变 Fact。新表名称为拟定接口，HW-005 冻结后统一生成迁移及测试。

| 新增表/扩展 | 关键字段与约束 |
| --- | --- |
| `schema_migrations` | 版本、迁移摘要、执行时间；不允许重复或倒序应用 |
| `investigation_sessions` | task/epoch、engineVersion、authorizationVersion、executionStatus、investigationStatus、revision |
| `entity_versions` | entityRef、versionRef、身份/内容断言、有效观察区间、sourceFactRef；按 task/epoch 隔离 |
| `relation_provenance` | edgeRef、端点版本、OBSERVED/DERIVED/INFERRED、sourceRefs、resolverVersion、时间误差 |
| `investigation_leads` | subjectRef、触发类型与版本、触发 Fact、优先级、状态；同主体/触发/观察轮次去重 |
| `investigation_hypotheses` | 主张、主体、来源、支持/反证引用、替代解释、状态与 revision |
| `investigation_obligations` | hypothesisId、义务类型、required、状态、结果、缺口；每项状态变更可审计 |
| `investigation_actions` | idempotencyKey、参数摘要、对象版本、依赖、授权版本、预算预留、状态、执行尝试 |
| `investigation_action_attempts` | actionId、attempt、ToolRun、开始/结束、结果/错误；保留首次失败 |
| `tool_runs` / `messages` / `queued_inputs` | Task + Epoch 控制面状态；迁移前无 Epoch 记录保留只读且不能被当前调查复用 |
| `investigation_events` | 递增 eventSeq、来源批次、事件类型、payload；与产生它的数据同事务提交 |
| `investigation_consumers` | consumer/version/task/epoch 的消费水位；恢复后增量处理 |
| `discovery_checkpoints` | 数据源、绑定快照/游标、扫描/匹配/返回数、范围、完整性 |
| Evidence metadata 扩展 | entityVersionRef、sourceKind、range、complete、sourceDigest、artifactDigest、采集前后检查 |

Action 唯一键至少包含 `task + epoch + actionKind + playbookVersion + entityVersion + argsDigest + observationRound`。授权变更触发重新校验，不能借更换 authorizationVersion 绕过去重或重放已完成的侵入式动作。

外键与 Repository 校验同时约束 task/epoch。所有状态更新使用 revision 条件更新，禁止两个执行路径重复领取同一 Action。

### 3.3 事务、崩溃与回滚

1. 保留当前单写者与 WAL 机制。迁移前暂停活动任务，检查可用空间，通过一致性备份接口或关闭连接并完成 checkpoint 后备份；不能只复制一个仍有未合并 WAL 的数据库文件。
2. 迁移在事务内执行，失败回滚。新版本启动前验证 schema 范围；旧程序遇到新 schema 明确拒绝写入。
3. FactBatch、同 Task + Epoch 的 STARTED ToolRun 终态和待消费事件同事务提交；ToolCall ID 与任务、Epoch、工具、重放策略和参数固定绑定，终态不得再次执行。规则消费的 Lead/Action 与消费水位同事务提交，保证重放不丢线索。
4. Evidence 文件系统与 SQLite 无法跨介质原子提交：先安全临时落盘、校验、原子重命名，再提交元数据；恢复时核对孤儿文件、未完成提交与摘要，不能虚构 Evidence。
5. 网络超时后的远端副作用不宣称 exactly-once。通过对象版本、artifact/动作回执和操作专属恢复策略获得可验证的幂等效果。
6. 软件回退恢复匹配的数据库备份与应用版本。新调查数据单独保留或导出，不在降级时静默删除；已保全 Evidence 和审批回执保留可核对清单。

## 4. 统一执行与模型接口

### 4.1 控制端 Action

```ts
interface InvestigationAction {
  actionId: string;
  taskId: string;
  epochId: string;
  kind: 'REMOTE_PRIMITIVE' | 'LOCAL_QUERY' | 'DERIVE' | 'MODEL_REVIEW';
  requestedBy: 'DISCOVERY' | 'PLAYBOOK' | 'MODEL' | 'ANALYST';
  obligationIds: string[];
  subjectRefs: string[];
  entityVersionRefs: string[];
  operationRef: string; // 原语、受限查询或版本化解析器引用
  argsDigest: string;
  dependsOn: string[];
  authorizationVersion: string;
  observationRound: string;
  idempotencyKey: string;
  status: 'READY' | 'RUNNING' | 'BLOCKED' | 'SUCCEEDED' |
          'PARTIAL' | 'FAILED' | 'CANCELLED';
  revision: number;
}
```

完整执行步骤：校验 schema → 解析引用和版本 → 校验当前授权 → 去重/依赖检查 → 预算预留 → 领取 Action → 调用固定原语 → 校验输出 → 保存证据及 FactBatch → 结算预算 → 验证义务 → 产生下一批事件。

遇到未知成本时记录保守预留和不确定成本；控制端超时不假定远端工作已停止。先尝试受控取消或状态核对，再决定是否可重试。M2 远端默认串行，后续仅在预算结算和目标负载测试通过后按资源类别开放有界并发。

### 4.2 模型本地提议接口

拟新增三个本地工具：

- `propose_hypothesis`：提交主张、主体、支持/反证引用、替代解释与待验证问题。
- `propose_actions`：组合已注册原语/解析器及依赖，绑定假设和义务；返回 accepted/rejected、原因和 Action 引用。
- `query_investigation`：查询线索、义务、动作、缺口及调查上下文，使用快照分页。

这些接口不接收 Shell、自由 SQL、模型生成的 collector 源码或自由目标路径。新颖假设可以组合已有动作，不能提交新执行能力。模型提议不得自填可信来源、完成状态或系统优先级。

现有直接原语调用迁移为 Action 提交的同步适配入口，共用相同执行器；同一任务不启动第二套远程执行循环。报告阶段只查询已经冻结的调查快照。

### 4.3 授权与配置

新增任务级 `focus` 与版本化 `authorizationEnvelope`。包络明确固定目标、namespace、Scope、可派生关系、敏感读取、原始证据采集、probe、时限和预算。

`focus` 调整调查优先级。DerivedObjectRequest 绑定来源 Fact 和白名单 resolver，Helper 复核真实对象后才能生成新引用；跨主机只产生交接线索。撤销授权时取消尚未执行动作，并在下一次数据出境前复核权限。

QUICK/STANDARD/DEEP 的预算和排序集中定义。新增配置只控制调查会话、资源和预授权策略，配置 Schema、默认值、设置页、配置迁移和文档一起更新。

## 6. 调查结束与资源策略的具体实现

### 6.1 状态分离

现有 TaskStatus 继续承载应用生命周期，但新增 investigationStatus 与 completionSnapshotRef。Runtime、Application 和 ReportService 不再各自决定“调查完成”。

完成校验器检查：发现范围是否处理、高优先级候选是否有状态、required obligation 是否满足或明确受限、Evidence 是否已校验、执行中动作是否终止、剩余不确定操作是否已登记。

- required obligation 被阻塞或不可获取：调查为 LIMITED，即使存在确认恶意的局部结论。
- 低优先级候选因预算未查完：记录未处理数量和范围；不能使用全范围未发现表述。
- Provider 失败：模型审查义务标为受限，已授权确定性动作继续。
- 分析师取消：停止发起新动作，处理取消和未知远端状态，报告使用取消时的快照。
- 报告失败：只影响报告生成状态，不能覆盖既有调查结论。

### 6.2 初版调度策略

优先级使用版本化离散排序：保全期限、必需义务、候选风险、预期区分能力、成本、等待时间。不要把模型自报的 0.99 当作统计概率。

起始预算分配建议为发现 30%、调查 45%、保全预留 20%、收尾 5%，仅作为 M2 基准实验配置。模型 Token、远端节点/字节/耗时和本地查询分别计账；它们的单位不同，不相互折算。空闲份额在策略允许时借用，但保全与收尾最低余额不可被普通模型调用耗尽。

Helper 扫描成本记录实际访问对象和处理字节，不能只按返回的 Fact 数量结算。资源限制尽可能覆盖外部子进程；无法精确限制的 probe 通过低并发、超时与运行前条件限制，并在 Capability 中说明。

## 7. 端到端验收矩阵

| 场景组 | 输入 | 必需结果 | 不能发生的结果 |
| --- | --- | --- | --- |
| 进程外连 | 主机＋网络线索 | socket→进程→脚本/映像→启动来源；证据和反证 | 依靠答案 PID/文件路径定位 |
| 零 IOC | 仅授权主机 | 至少一个多入口发现流程触发真实调查；无风险时范围明确 | 只运行 Preset 后生成泛化总结 |
| 易失执行体 | 可观测窗口内的已删除映像 | 尽早保全并记录端到端延迟；失败原因明确 | 重新打开同路径新文件冒充原样本 |
| 大量对象 | 1 千/1 万进程、10 万文件、日志轮转 | 分页可达、资源有界、扫描范围明确 | 静默漏页或空结果伪装全量未命中 |
| Web 攻击链 | 文件或进程任一入口 | 有效站点、内容、请求/执行关联、证据 | 仅靠 mtime 或 URL 字符串确认攻击链 |
| 账户与持久化 | Key/会话/unit 等入口 | 有效信任上下文与运行行为关联 | 把管理员权限配置直接确认成入侵 |
| Java | JVM/组件线索 | 精确 loader/context、证据与缺口 | partial 变成功、同名组件合并 |
| 良性干扰 | CMS/部署/更新/维护任务 | 候选可消歧；主张被反证或保持合理不确定 | 用规则强弱分数替代实证 |
| 来源受限 | 无 audit/日志被轮转/权限缺失 | LIMITED 且定位具体义务与受影响主张 | 把缺少事件当成没有执行 |
| 运行故障 | SSH/Provider/控制端重启 | 已提交事实不丢、可恢复动作续接、失败留痕 | 重复侵入式执行或预算归零 |
| 对抗输入 | 提示注入、伪造引用、跨任务证据 | 控制端/Helper 拒绝，审计可见 | 模型文本变为执行或授权来源 |

场景清单在运行前冻结，记录平台、规模、噪声、权限、目标可观测时间、规则/模型/流程包版本和预算。源事件由独立控制通道标注，不从最终 FactStore 反推真值。

### 7.1 指标与建议质量门槛

以下门槛在 HW-018 首轮冻结前作为提案；冻结后不能根据结果下调。任何调整建立新评测版本并保留旧结果。

| 指标 | 分母与计算 | 建议目标 |
| --- | --- | --- |
| 端到端发现率 | 正确定位主体且有支持证据的恶意场景 / 全部恶意场景 | 完整报告总体结果；预定义可观测层目标 ≥95% |
| 场景误报率 | 最终有效投影存在错误风险结论的良性场景 / 全部良性场景 | ≤5%，同时报告每主机候选、原始规则命中和最终风险结论数 |
| 关键证据保全率 | 已保存关键原始证据 / 独立真值中应可获取的关键证据 | 可观测层目标 ≥95%；全部样本和失去窗口的原因单列 |
| 关系准确率 | 被真值支持的直接/派生关系 / 被评估输出关系 | 推断另列；确认结论不得依赖已知错误关系 |
| 受限判定 | 正确标识缺口的预定义受限场景 / 受限场景总数 | 关键缺失场景全部明确受限 |
| 自主完成率 | 无额外人工提示且正确结束 / 全部任务 | 报告结果，明确额外授权与额外调查提示的区别 |
| 性能 | 首线索、捕获、Evidence 落盘、结束的 p50/p95 与 CPU/IO/内存/Token | 按基准负载冻结 SLO，未测前不承诺固定秒数 |

发布盲测起始规模至少 100 个恶意、100 个良性以及独立受限场景集，覆盖各类别和真实环境。开发集、调参集和盲测集按攻击行为/应用/家族切分，不能只改文件名增加样本。所有比例提供置信区间，各平台与类型分层；小样本通过不能外推总体可靠性。

M2 最小门禁使用至少 4 个恶意、4 个良性、4 个受限/故障端到端案例，验证闭环正确性；这一小集合不用于宣传召回率。M3 验证模型确实提出并执行新增调查动作，零远程调用的结果不能证明模型自主深挖。
